# gh-9s Release 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an interactive repo picker, pull requests (list, detail, checks that jump into Actions, terminal diff, comment/review/merge), and issue browsing and management to gh-9s.

**Architecture:** New screens register themselves through a small view registry (`tui/screen.go`) and live in their own files, so the existing `switch`-based views are not touched. All GitHub access stays in `internal/ghcli`; new pure logic gets its own packages (`internal/diff`, `internal/recent`) or pure functions next to the data types, so it is testable without a network. Overlays (repo picker, text/choice dialogs) are input modes of the model, like the existing trigger form.

**Tech Stack:** Go (run through `mise exec -- go ...`), Bubble Tea v1, lipgloss, the `gh` CLI. No new third-party dependency.

**Spec:** `docs/superpowers/specs/2026-10-25-gh-9s-release2-design.md`

## Global Constraints

- Language and UI stack unchanged (Go, Bubble Tea, lipgloss); no new third-party dependencies unless unavoidable.
- All GitHub access goes through the `gh` CLI, in package `ghcli`. Enterprise follows `gh`'s login.
- No irreversible action (merge, request changes, close) without an explicit confirmation step.
- No chatty API use: search is debounced, lists are fetched on demand and cached for a short time; the new screens (PR detail, diff, issue list, issue detail, picker) do not poll.
- No silent wrong target: every action names the repo and PR/issue number it will act on; new views and actions use `m.target`, not `m.base`.
- No network in unit tests: anything that runs `gh` is behind a package-level `var` the tests replace.
- Everything must work against any repo chosen with `:repo`, not only the current directory's.
- Each goal is merged as soon as it is green (`mise exec -- go vet ./... && mise exec -- go test ./... -race -count=1`).
- Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Diffs that are not plain text:** binary files, renames, a file with no trailing newline, an empty diff, CRLF content, and a diff longer than the cap. Expect: parsed without panic, shown or truncated with a note. (Task 8)
2. **`gh` JSON with nulls and empties:** a PR with no body, no reviews, no comments; an author that was deleted (`ghost`/null); a draft PR; `mergeStateStatus` of `UNKNOWN` while GitHub still computes it. Expect: rendered, never a crash; `UNKNOWN` is not offered as mergeable. (Tasks 5, 11)
3. **Picker search under pressure:** empty query, one-character global query, an API error, and results that arrive out of order. Expect: no request for too-short global queries, the error shown in the picker, and only the newest query's results displayed. (Task 4)
4. **Check links:** an Actions job URL, an Actions run URL, a non-Actions URL, an Enterprise host, and a check that belongs to a different repo than the PR's. Expect: Actions links open the graph in the right repo; everything else opens the browser. (Task 7)
5. **Acting on a PR/issue that is not in the expected state:** merge when no merge method is allowed or only one is, a PR already merged or closed, a merge attempted while checks are pending, a label with spaces or emoji, an issue with no assignees. Expect: the dialog explains and offers only what is valid; `gh` errors are shown, not swallowed. (Tasks 11, 14)
