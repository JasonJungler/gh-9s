# gh-9s Release 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add favorites, a live job graph, an input-driven trigger form, trigger-then-watch, log search and run-finished notifications to the existing gh-9s TUI.

**Architecture:** The app is a single Bubble Tea `model` in `main.go` with data fetchers in `gh.go`, all shelling out to `gh`. New logic goes in new focused files (`repo.go`, `workflow.go`, `favorites.go`, `form.go`, `trigger.go`, `graph.go`, `graph_render.go`, `notify.go`) that are pure and unit-tested; `main.go` only wires them in. Every `gh` call becomes repo-scoped through a `repoRef` so favorites work across repos.

**Tech Stack:** Go (via `mise exec -- go ...`), Bubble Tea v1, lipgloss, `gopkg.in/yaml.v3` (new), the `gh` CLI.

**Spec:** `docs/superpowers/specs/2026-10-24-gh-9s-release1-design.md`

## Global Constraints

- Language and UI stack stay Go, Bubble Tea, lipgloss; the only new dependency is `gopkg.in/yaml.v3`.
- All GitHub access goes through the `gh` CLI.
- The binary must be named `gh-9s` and ship via the existing tagged-release workflow (`.github/workflows/release.yml`).
- A favorite is identified by host, repo, and workflow file (e.g. `github.com/acme/api · deploy.yml`), stored in a personal config file outside any repo, never in the working tree.
- Graph styles: A = left-to-right boxes (default), B = top-to-bottom tree, C = timeline lanes; one key switches between them.
- If job dependencies cannot be determined, show the flat jobs list and say so; never draw a guessed graph.
- No per-keystroke requests; logs reload only while following; favorites' latest-run status is cached ~30s.
- macOS and Linux first.
- Run Go through mise: `mise exec -- go test ./...`. Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Workflow `on:` in every legal shape (`on: push`, `on: [push, workflow_dispatch]`, mapping form) and YAML 1.1 quirks where `on` parses as a boolean key. Expect: correct `dispatchable`, no error. (Task 2)
2. `needs:` that is a string, a list, references an unknown job, or forms a cycle. Expect: flat fallback, no hang or panic. (Task 7)
3. Missing, empty, or corrupt favorites file. Expect: missing/empty gives an empty list; corrupt gives an error shown to the user and the file is left untouched. (Task 3)
4. Zero jobs, one job, and a terminal narrower than any style needs (including width 0 before the first resize message). Expect: no panic; boxes fall back to tree. (Task 8)
5. Job display names that differ from job IDs, matrix names like `build (ubuntu, 1.22)`, and reusable-workflow names like `call / inner`. Expect: matched to the right spec and grouped. (Task 7)

### Task 7: Graph model

**Files:**
- Create: `graph.go`, `graph_test.go`
- Modify: `gh.go`

**Interfaces:**
- Consumes: `jobSpec`, `state`, `repoRef`.
- Produces:
  - `type runJob struct{ ID, Name, Status, Conclusion, Step, URL string; Start, End time.Time }`
  - `func fetchRunJobs(r repoRef, runID string) (jobs []runJob, headSHA, workflowPath string, err error)` using `gh run view --json jobs,headSha,workflowDatabaseId` plus the workflows list to resolve the path
  - `type gNode struct{ ID, Name, Label, Step string; State state; Start, End time.Time; Needs []int; Members []runJob }` (`Needs` are indices into `graph.nodes`; `Members` non-empty means a collapsed matrix or reusable-workflow group, and `Label` shows counts such as `3/8 ✓`)
  - `type graph struct{ nodes []gNode; flat bool; reason string }`
  - `func buildGraph(jobs []runJob, specs []jobSpec) graph`: matches a run job to a spec by exact `Name`; names starting with `<spec name> (` are matrix members; names containing ` / ` are grouped under the prefix before it; group state is failing if any member failed, running if any is running, else success; any unmatched job, unknown `needs` target, or cycle sets `flat=true`, a human `reason`, and one edge-less node per job
  - `func (g graph) stages() [][]int` topological layers (longest-path depth) as node indices, stable within a layer
